1 · Number Systems

Why computers use binary

Computers are built from transistors that are either on (1) or off (0). This two-state nature maps perfectly to the binary number system (base 2). All other data — numbers, text, images, sound — is ultimately stored as sequences of 1s and 0s.

💡 Key termA bit is a single binary digit (0 or 1). A byte is 8 bits. A nibble is 4 bits.

Place values in binary (8-bit)

Bit 7Bit 6Bit 5Bit 4 Bit 3Bit 2Bit 1Bit 0
128643216 8421
⚠️ Exam tipAlways write binary with leading zeros to fill 8 bits. e.g. 5 in binary is 00000101, not just 101.

Converting denary → binary

Example: convert 109 to binary.

109 ÷ 2 = 54 remainder 1
54 ÷ 2 = 27 remainder 0
27 ÷ 2 = 13 remainder 1
13 ÷ 2 = 6 remainder 1
6 ÷ 2 = 3 remainder 0
3 ÷ 2 = 1 remainder 1
1 ÷ 2 = 0 remainder 1

Read remainders bottom to top: 01101101 → ✅ 109

2 · Hexadecimal

Hexadecimal (hex) is base 16. It uses digits 0–9 then letters A–F for values 10–15. One hex digit represents exactly 4 bits (1 nibble), so 2 hex digits = 1 byte. This makes it far more compact than binary for humans to read.

Binary ↔ Hex conversion

Binary → Hex

Split the binary into groups of 4 bits from the right, then convert each group.

10110111
1011 = B   0111 = 7
Answer: B7

Hex → Binary

Convert each hex digit to a 4-bit group and join them.

3E
3 = 0011   E = 1110
Answer: 00111110

Binary addition example: 109 + 42 01101101 → 109 + 00101010 → 42 ────────── 10010111 → 151 ✓
🚨 Overflow errorOverflow occurs when the result of a binary addition is too large to fit in the available number of bits. With 8 bits, the max value is 255. Adding 200 + 100 would cause overflow.

Two's complement (negative numbers)

To represent negative numbers, computers use two's complement:

  1. Write the positive number in binary
  2. Flip all the bits (0→1, 1→0) — this gives the one's complement
  3. Add 1 to the result
Example: represent −42 in 8-bit two's complement 00101010 → +42 11010101 → flip all bits 11010110 → add 1 = −42 ✓

The most significant bit (leftmost) is the sign bit: 0 = positive, 1 = negative.

4 · Character Encoding

ASCII

American Standard Code for Information Interchange. Uses 7 bits → 128 characters (letters, digits, punctuation, control codes). Extended ASCII uses 8 bits → 256 characters.

A = 65 = 01000001
a = 97 = 01100001
0 = 48 = 00110000

Unicode

ASCII only handles English. Unicode supports every writing system. UTF-8 (variable length, 1–4 bytes) is the most common. UTF-16 uses 2 or 4 bytes. Unicode covers over 140,000 characters including emoji.

Downside: larger file sizes than ASCII.

🔑 ASCII trickLowercase letters are always exactly 32 more than their uppercase counterparts. A=65, a=97. You can convert case by flipping bit 5.

5 · Images

A digital image is made of pixels (picture elements). Each pixel is stored as a binary value representing its colour.

  • Resolution: number of pixels (width × height)
  • Colour depth: number of bits per pixel
Image file size formula
File size = width × height × colour depth
(answer in bits — divide by 8 for bytes)

Worked example

An image is 1024 × 768 pixels with a colour depth of 24 bits (True Colour).

1024 × 768 × 24 = 18,874,368 bits
÷ 8 = 2,359,296 bytes
÷ 1,024 = 2,304 KB
÷ 1,024 = 2.25 MB

6 · Sound

Sound is an analogue wave. To store it digitally, it must be sampled — its amplitude is measured at regular intervals and stored as a binary value.

  • Sample rate: how many samples per second (Hz / kHz). Higher = better quality.
  • Bit depth: how many bits per sample. Higher = more accurate amplitude.
  • CD quality: 44,100 Hz sample rate, 16-bit depth, stereo (×2).
Sound file size formula
File size = sample rate × bit depth × duration (s) × channels
⚠️ Nyquist's TheoremTo accurately reproduce a sound, the sample rate must be at least twice the highest frequency present. Human hearing tops out at ~20 kHz, hence CD's 44.1 kHz rate.

7 · Compression

Lossless compression

The original data can be perfectly reconstructed. No data is discarded. File size reduction is limited.

Examples: PNG, ZIP, FLAC, GIF

Used when accuracy is critical: text, code, medical images.

Lossy compression

Data is permanently discarded (usually imperceptible detail). Much smaller files, but quality degrades with repeated saving.

Examples: JPEG, MP3, AAC, MP4

Used for media where small quality loss is acceptable.

Run-Length Encoding (RLE)

RLE is a simple lossless algorithm. Instead of storing repeated values, it stores the value and a count.

Original: WWWWWBBBWWWWWWWWBBB RLE output: 5W 3B 8W 3B 19 characters → 8 values (saved 58%)

RLE works best when data contains long runs of the same value (e.g. simple images with large areas of the same colour). It performs poorly on complex or photographic images.
