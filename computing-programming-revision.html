Selection (IF / SWITCH)

2.2
IF score >= 70 THEN OUTPUT "Pass" ELSE IF score >= 50 THEN OUTPUT "Merit" ELSE OUTPUT "Fail" END IF
SWITCH day: CASE "Mon": OUTPUT "Monday" CASE "Tue": OUTPUT "Tuesday" DEFAULT: OUTPUT "Other day" END SWITCH
✅ Key Point Use IF/ELSE IF when conditions are ranges or complex expressions. Use SWITCH/CASE when comparing one variable against a list of specific values — it's cleaner.

Iteration (Loops)

2.3

FOR loop

Use when you know exactly how many times to repeat.

FOR i ← 1 TO 5 OUTPUT i NEXT i

WHILE loop

Checks condition before each iteration. May run 0 times.

WHILE x < 10 x ← x + 1 END WHILE

DO…UNTIL loop

Checks condition after each iteration. Always runs at least once.

DO x ← x + 1 UNTIL x = 10
❗ Common Mistake WHILE vs DO…UNTIL: if the condition is false from the start, a WHILE loop runs zero times but a DO…UNTIL loop always runs at least once. Examiners love testing this!

Arrays

2.4

Declaring and using a 1D array

# Declare an array of 5 integers (index 0 to 4) ARRAY scores[5] # Assign values scores[0] ← 87 scores[1] ← 65 scores[2] ← 91 # Loop through the array FOR i ← 0 TO 4 OUTPUT scores[i] NEXT i
💡 Key Facts about Arrays Arrays store multiple values of the same data type under one name. In AQA pseudocode, arrays are zero-indexed (first element is index 0). Arrays have a fixed size — you cannot add extra elements once declared.

Subroutines — Procedures & Functions

2.6

Procedure — does something, returns nothing

PROCEDURE greet(name) OUTPUT "Hello, " + name END PROCEDURE # Call it: greet("Gabriel")

Function — does something, returns a value

FUNCTION square(n) RETURN n * n END FUNCTION # Call it: result ← square(5) OUTPUT result # 25
🔑 Local vs Global Variables A local variable is declared inside a subroutine — it only exists while that subroutine runs and cannot be accessed elsewhere. A global variable is declared outside all subroutines and can be accessed anywhere. Local scope is preferred because it avoids accidental changes to variables from other parts of the program.
✅ Why use subroutines? Decomposition — break big problems into smaller parts. Reuse — write once, call many times. Easier testing — test each subroutine independently. Readability — code is easier to understand.
📂

File Handling

2.7

Reading and writing files in AQA pseudocode

# WRITING to a file open("scores.txt", "write") writeLine("scores.txt", "95") close("scores.txt") # READING from a file open("scores.txt", "read") WHILE NOT endOfFile("scores.txt") line ← readLine("scores.txt") OUTPUT line END WHILE close("scores.txt")
⚠️ Always close your file! Forgetting close() can cause data loss or file corruption. Examiners will mark you down if you omit it. Always open → read/write → close.
