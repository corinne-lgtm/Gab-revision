AQA 3.1 · Fundamentals of Algorithms

What is an algorithm?

Learn the three ideas behind computational thinking.

Algorithm

A clear, finite sequence of steps to solve a problem or complete a task. A program is an implementation of an algorithm in code.

Example: instructions for deciding whether a pupil is old enough to join a club.

Decomposition

Breaking a large problem into smaller, manageable tasks.

Example: school lunch ordering → choose meal, check payment, print receipt.

Abstraction

Removing details that do not affect the solution.

Example: to calculate a bus fare, you need journey zones, not the passenger’s favourite colour.

Exam trap: decomposition breaks a problem apart; abstraction ignores irrelevant detail. They are not the same thing.

Input → Process → Output

Input: age = 15→Process: age ≥ 13?→Output: “Allowed”

When tracing a given algorithm, find its inputs, the steps that process them and the resulting outputs.

Represent the same solution in two different ways.

Decisions normally have labelled Yes/No (or True/False) branches.

Pseudocode: age check

age ← INPUT
IF age >= 13 THEN
OUTPUT "Allowed"
ELSE
OUTPUT "Not allowed"
ENDIF

Pseudocode describes the logic without needing a particular programming language. In the exam, use the form the question asks for.

Worked example

With input age = 12, the condition is false, so the output is Not allowed.

Remember: arrows show the direction of the flow. A decision is a question with different paths. A loop returns to an earlier step while its condition requires repetition.

Algorithm efficiency

Choose a faster approach, without complicated formulas.

Time efficiency

Two correct algorithms may take different amounts of time. For AQA, compare the number of steps / comparisons in a given scenario; you do not need formal Big-O calculations.

Example: checking each of 1,000 names one by one may take many comparisons; repeatedly halving a sorted list can take fewer.

Fair comparisons

Compare algorithms using a comparable input, and discuss when one is more suitable. A faster method may require extra preparation, such as sorting data first.

Exam phrase: “Binary search is generally faster on a sorted list because it discards half the remaining items each step.”

Don't write: “binary search is always better.” It requires a sorted collection; linear search can work on unsorted data.

Linear search & binary search

See every comparison and understand why sorting matters.

Linear search — any list

Start at the first item, compare with the target, then move on until found or the list ends.

[14, 3, 27, 8, 19, 35, 42]

Binary search — sorted list ONLY

Check the middle item. If the target is smaller, discard the higher half; if larger, discard the lower half. Repeat.

[3, 8, 14, 19, 27, 35, 42]

Search comparison

Bubble sort

Swap neighbouring values until the list is ordered.

How it works

Compare adjacent pairs. If they are in the wrong order, swap them. Work across the list repeatedly, until a full pass makes no swaps.

Example: 5, 2, 4 → swap 5 and 2 → 2, 5, 4 → swap 5 and 4 → 2, 4, 5.

One pass can move the largest remaining item to the end.

Interactive bubble sort

Watch one comparison at a time.

Exam trap: one pass through a list does not necessarily finish sorting it.

Merge sort

Split → sort → merge, comparing values as you combine lists.

Worked merge sort

[7, 2, 6, 1]↓ split[7, 2] [6, 1]↓[7] [2] [6] [1]
[2, 7] [1, 6]→ merge[1, 2, 6, 7]

Divide the list into smaller lists until each contains one item. Then merge the sorted parts by repeatedly taking the smaller front item.

Merge sort

Usually performs well on larger lists, with predictable splitting and merging. It generally uses extra memory to hold temporary merged lists.

Bubble sort

Easy to describe and implement, but repeatedly compares neighbours and can require many passes on a long unsorted list.

Exam technique & common mistakes

Answer exactly what the question asks.

Describe an algorithm (3 marks)

1. Say what the algorithm starts with.
2. Explain the repeated action or decision.
3. State how it stops / returns a result.

Compare two algorithms (4 marks)

Give an advantage and a limitation, tied to the question’s data, then make a justified choice.

Frequent mistakes: forgetting to sort before binary search; confusing decomposition with abstraction; tracing the wrong value after a swap; saying merge sort simply swaps adjacent values; mixing up a flowchart decision and a process.
