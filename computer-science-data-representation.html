Number bases

Why computers use binary, decimal and hexadecimal

Decimal · base 10

Our everyday number system. Digits 0–9. Place values are powers of 10.

253 = 2×100 + 5×10 + 3×1

Binary · base 2

Only 0 and 1. Computers store and process data using binary bit patterns.

1011₂ = 11₁₀

Hexadecimal · base 16

Digits 0–9 and A–F; A means 10 and F means 15.

2F₁₆ = 47₁₀

Why binary?

Digital circuits can distinguish two states reliably (on/off). The same bits can stand for an integer, letter, colour, sound or instruction depending on how they are interpreted.

Why hexadecimal?

It is much shorter and easier for humans to read than a long binary string. Every 4 binary bits correspond to exactly 1 hex digit. Computers still store the underlying data in binary.

Converting between bases

Binary ↔ decimal ↔ hexadecimal, up to 255

Binary → decimal

  1. Write the place values: 128 64 32 16 8 4 2 1.
  2. Add the place values where the binary digit is 1.

00101101₂ = 32 + 8 + 4 + 1 = 45.

Decimal → binary

  1. Take the largest power of 2 that fits.
  2. Subtract and continue down the place-value columns.

45 = 32 + 8 + 4 + 1 → 00101101₂.

Binary ↔ hex

Split bits into groups of four, starting from the right. Convert each group separately.

1101 0110 → D 6 → D6₁₆.

Conversely, 3A → 0011 1010.

Decimal ↔ hex

Divide by 16. The quotient is the first hex digit, the remainder is the second (for values 0–255).

173 ÷ 16 = 10 remainder 13 → AD₁₆.

3F₁₆ = 3×16 + 15 = 63.

Exam trap: the maximum 8-bit unsigned value is 255, not 256. That is because 00000000 is a value too.

AQA 3.3.3

Units of information

Bits, bytes, kB, MB, GB, TB

bit · b

A single 0 or 1.

1 b = one bit

byte · B

Exactly 8 bits.

1 B = 8 b

Capital letters matter

MB = megabytes; Mb = megabits. Not the same size.

Learn AQA's decimal prefixes

1 kB = 1,000 bytes
1 MB = 1,000 kB
1 GB = 1,000 MB
1 TB = 1,000 GB

AQA uses decimal prefixes here (multiples of 1,000). Older sources sometimes use 1,024; do not mix them in these questions.

Worked example

How many bytes are in 2.5 MB?

2.5 × 1,000 × 1,000 = 2,500,000 bytes

How many bits? Multiply the byte total by 8 → 20,000,000 bits.

Binary arithmetic

Addition and logical shifts

Binary addition

Add from right to left, carrying when necessary.

  00001011
+ 00000101
──────────
  00010000

11 + 5 = 16. Check in decimal.

Rules: 0+0=0; 0+1=1; 1+1=10 (write 0, carry 1); 1+1+1=11 (write 1, carry 1).

Logical binary shift

Left shift moves bits left, puts zeroes on the right and multiplies an unsigned number by 2 for each place, provided no significant bits are lost.

00000101 → 00010100

Shift left 2: 5 × 4 = 20.

Right shift moves bits right, adds zeros on the left and performs whole-number division by powers of 2 (discarding remainders).

Try shifting a number

8-bit logical shifts; bits going beyond the boundary are discarded.

Exam trap: shifts do not rotate bits around. Bits that fall off the edge disappear.

Character encoding

ASCII, Unicode and character codes

What is character encoding?

A character set is a collection of characters with assigned numeric codes. Computers store the codes as binary.

For example, capital A in ASCII has decimal code 65 (binary 1000001).

ASCII vs Unicode

7-bit ASCII has 2⁷ = 128 possible codes.

Unicode supports many more writing systems and special symbols, so text can be shared internationally. Its first 128 code points match ASCII.

Use code patterns

ASCII uppercase letters run consecutively: A = 65, B = 66, C = 67 … Z = 90. Lowercase a = 97, b = 98 …

A65
B66
C67
D68
E69
Exam phrase: Unicode can represent a much wider range of characters than 7-bit ASCII, including characters from different languages. This is an advantage, not simply "Unicode is newer".

Representing images

Pixels, colour depth and file size

What is a pixel?

A picture element: one tiny coloured square. A bitmap is a grid of pixels.

Resolution / image dimensions: width × height, counted in pixels.

Colour depth

Bits used to store each pixel. With n bits, a pixel can have 2ⁿ possible colours.

1 bit → 2 colours; 8 bits → 256 colours; 24 bits → 16,777,216 possible colours.

Make your own 8 × 8 bitmap

Click squares to make a 1 (filled) or 0 (empty). Each row below represents 8 bits.

Calculate image size

bits = width × height × colour depth
bytes = bits ÷ 8

Example: 200 × 100 pixels, 8-bit colour depth → 200 × 100 × 8 = 160,000 bits = 20,000 bytes.

More pixels or greater colour depth means more uncompressed data. These GCSE calculations ignore extra file metadata.

AQA 3.3.7

Representing sound

Sampling and sound file size

Analogue → digital

Real-world sound is a continuously changing analogue wave. To store it, the computer measures the wave's amplitude at regular intervals. Each measurement is a sample.

Sampling rate = samples each second, measured in hertz (Hz).

Sample resolution

The number of bits per sample. More bits allow more distinct amplitude levels to be represented.

A higher sampling rate captures the waveform more frequently. Both typically increase uncompressed file size.

Sound as samples

Blue curve: analogue sound. Yellow dots: amplitude measurements taken at regular time intervals (illustrative).

Calculate file size

bits = sampling rate × sample resolution × seconds

For 10 seconds at 8,000 Hz and 8 bits per sample:

8,000 × 8 × 10 = 640,000 bits

÷ 8 = 80,000 bytes.

Use AQA's basic single-channel formula unless a question gives additional information.

AQA 3.3.8

Data compression

RLE and Huffman coding

Why compress data?

Compression reduces the number of bits needed to store or transmit data. Smaller files can save space and transfer faster.

Lossless: the original can be reconstructed exactly. Lossy: some information is permanently removed. RLE and Huffman coding are lossless.

Run Length Encoding (RLE)

Store repeated characters as count + value pairs.

0000011100
→ (5,0) (3,1) (2,0)

It works best with long runs; lots of alternation may not save space. For bitmap questions, encode rows separately.

Try RLE on a row

Huffman tree

Common symbols get shorter codes

Follow the branches from the top: left = 0, right = 1. No complete code is the beginning of another code.

A = 0
B = 10
C = 110
D = 111

Encode ABAC:

0 | 10 | 0 | 110

= 0100110 → 7 bits.

At 7-bit ASCII, 4 characters would require 28 bits (ignoring the tree storage overhead).

Exam technique: when asked to calculate Huffman size, multiply each character's code length by how often it appears, then add the results. The tree or codes are usually supplied.
