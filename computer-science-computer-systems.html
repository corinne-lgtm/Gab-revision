Hardware and software

The physical machine and the instructions that control it

Hardware = something physical

Hardware is the physical equipment you can touch: CPU, RAM chips, keyboard, screen, motherboard and SSD.

Example: a keyboard sends input to the computer.

Software = instructions

Software is the programs and data instructions telling hardware what to do: operating systems, apps and games.

Example: a word processor tells the CPU what operations to perform and the screen what to display.

How they work together

1. Input

Keyboard detects a key press.

2. Process

Software instructions are carried out by the CPU.

3. Output

Monitor displays the character.

Key idea: hardware needs instructions to be useful; software must run on hardware.

AQA exam phrase: Hardware is the physical components of a computer system; software is the programs/instructions executed by the hardware.

Boolean logic

NOT, AND, OR, XOR — then combine gates in circuits

Four logic gates

GateRule
NOTReverses the input: 0→1, 1→0
AND1 only if both inputs are 1
OR1 if at least one input is 1
XOR1 if the inputs are different

How to approach a truth table

  1. List every input combination (two inputs → four rows; three → eight).
  2. Work through the circuit gate by gate, using intermediate columns.
  3. Write the final output for each row.

Three inputs: 000, 001, 010, 011, 100, 101, 110, 111.

Boolean expressions

A . B means A AND B.

A + B means A OR B.

A ⊕ B means A XOR B.

NOT A can be shown as A with a bar above it.

Example: (A . B) + NOT C = (A AND B) OR (NOT C).

Building a circuit

For (A AND B) OR (NOT C):

  1. Feed A and B into an AND gate.
  2. Feed C into a NOT gate.
  3. Feed those two outputs into an OR gate.

Work inside brackets first. With A=1, B=0, C=0: AND=0; NOT C=1; final OR=1.

Three-input circuit simulator

Exam trap: OR includes the case A=1, B=1; XOR does not. AQA uses NOT, AND, OR and XOR (not NAND or NOR).

Software classification

System software, applications, operating systems and utilities

System software

Software that manages computer resources and provides the platform on which applications run.

Examples: operating systems and utility programs.

Application software

Software that performs a task for an end user.

Examples: web browser, photo editor, spreadsheet, music player.

Careful: a web browser is an application, not an operating system.

What does the operating system manage?

Processor

Schedules processor time between running programs.

Memory

Allocates RAM and keeps processes from interfering.

I/O devices

Controls communication with peripherals through drivers.

Applications

Loads, starts and manages software processes.

Security

Manages user accounts, permissions and access.

User interaction

Provides an interface such as a GUI or command line.

Utilities

Utility software helps maintain, protect or manage a system.

Examples: antivirus scanner, backup tool, disk cleanup tool, file-compression utility.

Exam scenario

Question: A student wants to edit a photograph and keep their files safe.

Answer: photo editor = application software; backup program = utility/system software.

Exam tip: “The OS manages the computer” is too vague for a 2–3 mark question. Name a resource and describe how it is managed.

Programming languages and translators

High-level vs low-level languages, machine code, compilers, interpreters and assemblers

High-level language

Closer to human language and easier to read, write, debug and maintain.

Often portable between systems when a suitable translator exists. Example: Python.

Needs translation before execution.

Low-level languages

Closer to the processor: machine code (binary instructions) and assembly language (mnemonics like ADD or MOV).

Often processor-specific; offers finer hardware control but is harder to write and maintain.

Translation pathways

Compiler

Translates a whole high-level program into machine code before running. Produces executable/translated output.

Interpreter

Executes program statements by interpreting them as the program runs. Does not produce a standalone machine-code translation directly.

Assembler

Translates assembly instructions into machine-code instructions, generally one-to-one.

Choosing a translator

Compiler: useful when distributing a compiled executable and for repeated execution.

Interpreter: useful during iterative testing because statements can run without a separate full compilation step.

Assembler: required to turn assembly code into machine code.

Why not write everything in assembly?

Assembly can offer close hardware control, often valuable in embedded systems and device-level programming.

But large programs take more time to develop, debug and maintain than high-level equivalents.

Precise exam wording: the CPU executes machine code. Assembly uses mnemonics and must be assembled; high-level languages need a translator.

Systems architecture

CPU components, memory, storage, performance, cloud and embedded systems

CPU components

ALU: performs arithmetic and logical operations.

Control Unit (CU): coordinates the instruction cycle and controls other parts.

Clock: sends regular timing pulses that synchronise CPU activity.

Registers: tiny, very fast locations inside the CPU for data/instructions being used.

Buses: connections carrying data and signals between components.

CPU performance

Clock speed: more cycles per second can increase performance (but does not guarantee it).

Cores: more cores can process multiple tasks/threads in parallel when software supports it.

Cache size: larger cache can reduce slow RAM access by storing frequently used information near the CPU.

Fetch → Decode → Execute

1. FETCH

Get the instruction

CPU retrieves the next instruction from main memory.

2. DECODE

Work out what it means

The control unit interprets the instruction.

3. EXECUTE

Carry it out

CPU performs the action, possibly using the ALU or memory.

RAM vs ROM

RAM: main working memory holding programs/data currently in use. Volatile — contents lost when power is off.

ROM: non-volatile memory, commonly storing firmware/start-up instructions.

Volatile = needs power to retain content; non-volatile = retains content without power.

Registers, cache and secondary storage

Registers: tiny, fast CPU storage.

Cache: very fast memory storing frequently accessed data/instructions to reduce RAM access.

Secondary storage: persistent storage (SSD or hard disk) not directly accessed as main memory by the CPU.

Memory and storage comparison

TypeVolatile?Typical purpose
RegistersYesImmediate CPU operations
CacheYesFrequently used data/instructions

Magnetic hard disk (HDD)

Stores bits by magnetising areas of a spinning disk; a moving read/write head accesses data.

Advantages: generally cheaper per GB, large capacities.

Disadvantages: moving parts, slower access, more susceptible to mechanical damage.

Solid-state drive (SSD)

Stores information electronically in non-volatile memory chips, with no moving parts.

Advantages: fast access, robust to movement, quiet.

Disadvantages: often higher cost per GB, finite write endurance.

Cloud storage

Data is stored on remote servers accessed over a network/internet; the servers still use physical SSDs and/or magnetic storage.

Benefits: access from multiple places, sharing, off-site backups.

Risks: depends on connectivity, ongoing cost, privacy/security considerations and service availability.

Embedded systems

A computer designed for a specific function as part of a larger device, such as a washing machine controller or car ABS system.

Unlike a general-purpose laptop, it is usually optimised for one set of tasks, often under resource and power constraints.

Choose the best storage for a scenario

Think about speed, price per GB, portability and reliability.

Exam technique: if asked to compare two options, explain which feature matters for the stated user/scenario, not just a list of generic benefits.
