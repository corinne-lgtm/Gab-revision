What is cyber security?

Protecting devices, networks and information

The definition

Cyber security means the processes, practices and technologies used to protect networks, computers, programs and data from attack, damage and unauthorised access.

It protects information and the systems that store or transmit it.

What are we trying to protect?

Confidentiality: only authorised people can read private data.

Integrity: information is not changed without permission.

Availability: systems and data remain usable when needed.

These three ideas help explain the purpose; AQA expects the core definition above.

Exam technique: “keeps computers safe” is too vague. Specify what is protected and from what.

Social engineering

Tricking people instead of attacking code

The weak point is the person

Social engineering means manipulating a person into revealing confidential information or doing something unsafe. The attacker may pretend to be trustworthy or create urgency.

Phishing

A fake email or text asks you to reveal private information or visit a fraudulent site.

Clue: “Your account will close in 10 minutes — click here.”

Blagging (pretexting)

The attacker invents a believable story or identity to persuade someone to disclose information or take action.

Clue: “I'm from IT support; tell me your login so I can fix the problem.”

Shouldering

Also called shoulder surfing: watching someone enter private information, such as a PIN or password.

Clue: looking over a person's shoulder at a cashpoint.

Protection: verify requests using an official contact channel, never share credentials, cover the keypad, and train users to recognise scams.

Malware

Spot viruses, trojans and spyware

Malware = malicious software

Malware is software designed to cause harm, interfere with systems, steal information or allow unauthorised access.

Computer virus

Malicious code that attaches to a file or program and spreads when infected files/programs run or are shared.

Trojan

Malicious software disguised as legitimate software to trick the user into installing it. It does not need to self-replicate.

Spyware

Software that secretly monitors activity or collects information, such as browsing activity or typed data.

Common mix-up: a trojan pretends to be safe; a virus infects other files; spyware secretly watches or gathers data.
Protection: trusted downloads, anti-malware scans, user permissions, and software updates reduce risks. No single measure guarantees safety.

Other cyber threats

The less obvious ways systems become vulnerable

Pharming

Redirects a user to a fake website, even when they intended to visit a legitimate one. A fake login page can steal credentials.

Different from phishing: phishing often tricks you through a message; pharming redirects web traffic.

Weak or default passwords

Easy-to-guess or factory-set passwords can let attackers sign in. Use unique, strong passwords and change default credentials.

Misconfigured access rights

If permissions are too broad, an ordinary user might view or edit private files. Apply least privilege: give users only the access they need.

Removable media

An infected USB drive could introduce malware; a lost drive could expose files. Restrict unknown devices and encrypt sensitive data.

Unpatched or outdated software

Known security weaknesses may remain exploitable if fixes have not been installed. Apply trusted updates promptly.

Exam shortcut

For every threat, learn a cause → risk → prevention chain. Examiners reward a specific explanation, not just a keyword.

Penetration testing

Finding weaknesses before criminals do

What is a penetration test?

An authorised simulated attack on a system to find security weaknesses so they can be fixed. The tester tries to access protected resources as an attacker might, but with permission and agreed boundaries.

Insider-style test

The tester has some knowledge or basic credentials for the target. This simulates a malicious insider or a compromised internal account.

Outsider-style test

The tester has no prior system knowledge or credentials. This simulates an external attacker attempting to break in.

Which test is it?

A tester is given a low-level employee account before examining the school's security.

Think about what the tester already knows.

Security measures

How to prevent and detect threats

Biometrics

Use a physical characteristic, such as a fingerprint or face, to verify identity — common on phones.

Password systems

Require users to prove their identity. Strong, unique passwords reduce the risk of guessing or reused credentials.

CAPTCHA

A test designed to distinguish humans from automated bots, helping limit automated form abuse.

Email confirmation

A confirmation link or code verifies access to the supplied email account when registering or making a change.

Automatic updates

Install patches that fix known software vulnerabilities without relying entirely on manual updates.

Defence in layers

Combine different methods: a strong password doesn't stop someone reading it over your shoulder, and updates don't stop every phishing scam.

Threat or protection?

Practise applying the concepts to real situations

Build an exam-ready explanation

For a 3–4 mark scenario question, structure your answer in this order:

  1. Identify the threat by name.
  2. Explain how it could cause the problem in this situation.
  3. Recommend a protection method.
  4. Link the protection to the specific risk.

Practise with a school scenario

A school employee receives a text claiming to be from the IT department. It demands their password to avoid losing access.

Weak answer

“This is a scam. Be careful.”

Not enough technical detail or explanation.

Strong answer

“This is phishing: a fraudulent message attempts to collect login details. The employee should not reply and should verify it through the school's official IT contact. This prevents giving credentials to the attacker.”
